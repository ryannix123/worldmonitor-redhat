# World Monitor as a self-updating appliance

Runs the full World Monitor stack on a small Fedora box (a NUC, a mini-PC,
anything with ~4 GB RAM to spare) as a set of rootless containers that start
at boot, update themselves nightly, and roll back on their own if an update
breaks. Designed for a machine nobody logs into.

Same five containers and the same images as [`../podman/`](../podman/README.md);
the difference is *how they're run*: systemd units generated by Podman's
Quadlet instead of a compose file, so the OS owns the lifecycle.

```
                     nightly 07:00 UTC                    05:00 local
  GitHub Actions ──── builds on fresh UBI ───▶ Quay ◀──── podman-auto-update
  (worldmonitor-redhat)                                   │
                                                          ▼
                                            pull ▸ restart ▸ healthcheck
                                                          │
                                              healthy? ── yes ─▶ done
                                                          └── no ──▶ roll back
```

## Install (once)

On a fresh Fedora install (Workstation or Server), as root, from this directory:

```bash
sudo ./install.sh                      # prompts for the OpenRouter key
sudo ./install.sh --env ../podman/.env # or reuse keys from an existing local setup
```

That's the whole install. It creates a service user `wm`, drops the units in
`~wm/.config/containers/systemd/`, generates the internal secrets (same formats
as `podman/deploy.sh`), pulls the images, starts the stack, and enables the
timers. Re-running it is safe.

Then open `http://wm-armory.local:3000` from any machine on the LAN (or
`http://<ip>:3000`). The map and news are immediate; conflict/military panels
take 2–3 minutes; market/economic panels fill after the first seed pass
(15–20 min).

For a wall display, also run `sudo ./kiosk/setup-kiosk.sh` — GNOME auto-login,
Firefox in kiosk mode, screen never blanks. (Needs Fedora Workstation.)

## What's in here

| Path | Purpose |
|---|---|
| `install.sh` | idempotent installer (packages, user, firewall, units, secrets, timers) |
| `env.example` | template for `~wm/.config/worldmonitor/.env` — the only file with secrets |
| `quadlet/*.container` | one unit per container; mirrors `compose.local.yml` line for line |
| `quadlet/*.network`, `*.volume` | the private network and the Redis data volume |
| `seed-loop.sh` | the hourly seeder loop (mounted into the `seeders` container) |
| `systemd/podman-auto-update.timer.override.conf` | pull schedule: 05:00 local |
| `systemd/wm-weekly-reboot.*` | Sunday 04:30 reboot (kernel updates, browser memory) |
| `kiosk/` | optional wall-display mode |
| `OFFICE-CARD.md` | one page to print and leave next to the box |

## How updates work

`podman-auto-update.timer` runs `podman auto-update` daily at 05:00. For each
container whose unit carries `AutoUpdate=registry`, it compares the image
digest on Quay with the running one; if it changed, it pulls and restarts that
unit. Because every long-running unit has `Notify=healthy`, systemd only
counts the restart as successful once the container's healthcheck passes —
and if it doesn't, `podman auto-update` **rolls back to the previous image**
and restarts again. A bad nightly build therefore costs one failed restart at
5 a.m., not a dead dashboard when people walk in.

OS packages update via `dnf-automatic` (security updates, applied
automatically). The Sunday reboot picks up kernels.

To see what tonight would do without doing it:

```bash
sudo -u wm XDG_RUNTIME_DIR=/run/user/$(id -u wm) podman auto-update --dry-run
```

## Day-2 commands

All as the `wm` user's systemd instance (the `sudo -u wm XDG_RUNTIME_DIR=…`
prefix is what makes `systemctl --user` work from a root shell):

```bash
WM='sudo -u wm XDG_RUNTIME_DIR=/run/user/'$(id -u wm)
$WM systemctl --user status worldmonitor ais-relay redis-rest redis seeders
$WM podman logs --tail 50 worldmonitor
$WM podman logs -f seeders | grep -E 'OK|SKIP|FAIL|Done:'
$WM systemctl --user restart worldmonitor seeders     # after editing .env
$WM podman auto-update                                # update right now
```

**Change or add API keys:** edit `~wm/.config/worldmonitor/.env`, then restart
`worldmonitor` and `seeders`. **Change what the wall shows:** edit `KIOSK_URL`
in `~wm/.config/worldmonitor/kiosk.sh`.

**Roll back by hand** (rare — auto-update already does this on failure):
`$WM podman auto-update --rollback` isn't a thing, but every build is also
tagged by upstream commit on Quay; set `Image=` in the unit to a specific
`<sha>` tag, `daemon-reload`, restart.

## Design notes

* **Rootless.** Everything runs as `wm`. The images already run as UID 1001
  (the OpenShift restricted-SCC pattern), so nothing here needs root, and a
  compromised container has no path to the host.
* **One `.env`, all containers.** For simplicity every unit reads the same env
  file, which means the Redis container can technically see the OpenRouter key.
  Acceptable on a single-purpose appliance; if it bothers you, split the file
  and point each unit's `EnvironmentFile=` at its own.
* **No inbound access needed.** The box only makes outbound connections (image
  pulls, data feeds, OpenRouter). Remote support is "share your screen on a
  call," not a VPN — nothing to explain to campus IT beyond "a LAN-only
  dashboard on port 3000."
* **Floating `latest`.** These tags track upstream `main` via the nightly
  build, so the appliance is always on current code. The rollback path is
  what makes that safe unattended.

## Uninstall

```bash
sudo -u wm XDG_RUNTIME_DIR=/run/user/$(id -u wm) systemctl --user stop worldmonitor seeders ais-relay redis-rest redis
sudo rm -rf ~wm/.config/containers/systemd ~wm/.config/worldmonitor
sudo loginctl disable-linger wm && sudo userdel -r wm
sudo systemctl disable --now wm-weekly-reboot.timer
```
